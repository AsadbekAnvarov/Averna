### 2 — Band forecast and path to target (done)

The pure model `lib/forecast/band-forecast.ts` (runs on server and client) fits a recency-weighted linear trend per skill over the last 120 days (weight halves every 30 days). The slope is clamped to −0.25…+0.5 band per 30 days, the what-if included. "Now" is the fitted line at today. The range is the weighted residual SD (at least 0.25) × (1 + 1/√n), floored/ceiled to half bands.
Honesty rules: fewer than 2 results → "Take 1 more Listening test to see your forecast"; results less than 7 days apart → too early (level only, date when a trend becomes possible); slope ≤ 0 → flat, so no date, advice instead. The path is the day the line reaches target − 0.25 (which IELTS rounds to the target) within 365 days, with an earliest–latest window and a before/after-exam check. The overall uses the IELTS rule on the four half-band "nows", and only when all four skills have a forecast.
Evidence comes from the progression engine's cached `loadSessions`. Only full-ish attempts count (the XP minimums: ≥ 10 questions, Writing/Speaking word and second floors), and only the first attempt of a paper or prompt (retakes are memory-inflated). Pace is sessions per week over the last 4 weeks. The what-if multiplies the slope by 1 + 0.15 × extra sessions per skill a week, capped at ×1.6.
UI: Progress (page and tab) opens on `BandForecastCard`: overall "Now ≈ X.X (range) · at this pace 7.0 by …", four skill rows with an accessible sparkline (past results + dashed projection), trend arrow, path window or a practice link, a 0 / +1 / +2 / +3 segmented what-if with an aria-live summary, and the footnote "Estimates from N results. Real exam conditions vary."
Today: `PathToTargetCard` ("Path to 7.0" + exam date, same `averna_exam_date` key) sits under the streak and links to `/progress#forecast`.
Replaced: Exam Countdown (merged into Path to target), and BandProgress / "Practice evidence" on Progress, the Progress tab and `/learning` (where the compact card now sits beside the Skill Radar). `PracticeReadiness` stays behind the AI Clone entry point. The Progress tab now opens on the forecast; Skill Radar pairs with Level, and Weekly goal sits under DNA + achievements.

### 5 — Show me where (done)

The pure locator `lib/review/evidence.ts` finds the sentence that answers each wrong or blank question. Explicit quotes come first: the ‘…’ / “…” / '…' segments of the explanation, matched despite whitespace, quote-mark and case noise, then punctuation-blind, then by token overlap. Without a usable quote it derives the sentence: the gap answer as an exact phrase dominates, then shared content words from the explanation, question, template line and accepted option (stop-words out, light stemming, rarer words weigh more), with "Paragraph C" / "sixth paragraph" references preferred (required when the answer or question names the paragraph). Below the threshold it returns null instead of a random sentence. On the built-in papers 318 of 320 questions resolve from quotes and 2 are derived.
Reading result: each mistake gets "Show in text". On desktop the passage sits beside the answers (sticky, own scroll) and the sentence is highlighted in place. On phones a bottom sheet opens on the sentence with "Back to question N". The highlight is a `<mark>` in the exam highlight colour (no padding, so no layout shift), focused with tabindex −1 and announced ("Evidence for question 7 highlighted"); a second tap ("Hide") removes it.
Listening result: the page now loads each part's ready recording (`listeningClientContent`, after submission only) into a small result player. "Hear it" plays from the evidence time − 2 s (the line's timeline start plus the evidence's share of the line); "Show in transcript" highlights the transcript sentence the same way. Single-file recordings have no line timeline, so they get the transcript only.
"Your mistakes by type" sits beside "Accuracy by question type" (DashRow, owner only): "Matching headings — 3 of 5 wrong → Practise matching headings" links to one part of another test of the same skill. The picker `lib/review/practice-by-type.ts` goes through: another paper not done yet → another paper → this paper. Catalog summaries now carry per-part kinds, with matching split into headings / information (`practiceKindOf`). Done keys come from a key-only SQL projection.

### 8 — Native-language hints and comfort settings (done)

Comfort prefs live in one pure module, `lib/comfort/prefs.ts`: typed values, localStorage keys (`averna_text_scale` as before, plus `averna_font`, `averna_line_spacing`, `averna_contrast`, `averna_ruler`, `averna_l1`, `averna_l1_when`), parse / serialize with per-field defaults for garbage, prefs → `<html>` classes, and `savePrefs`, which writes only the changed keys, applies the classes and fires `averna-comfort`. Settings and the dashboard's Customize panel both use it; their copied apply code is gone.
`COMFORT_SCRIPT` (an inline `<head>` script beside `THEME_SCRIPT`, built from the same class map) applies text size, readable font, line spacing and contrast before the first paint on every page. That fixes a bug: a saved Large text size used to come back only once the Customize panel mounted. On a first visit with the system's "more contrast" setting on, contrast starts at High and is saved, so it can be switched off.
Settings → Reading comfort (all roles), with a live preview paragraph:
- Readable font: Atkinson Hyperlegible via `next/font`, not preloaded, `--font-readable`, with letter-spacing 0.02em and word-spacing 0.08em. Code and the Mock CDI keep their fonts; the practice exam shell follows it.
- Line spacing Normal / Relaxed / Loose: line-height 1.75 / 2.0 on reading text through low-specificity `:where()`. Deliberately tight elements and anything inside nav, buttons, labels, tables, tab lists or the Mock CDI keep theirs.
- High contrast: token overrides for both themes. Muted text is ≥ 4.5:1, borders are stronger, glass surfaces are opaque (no blur) and the focus ring is a 3 px outline.
- Reading ruler: a fixed band, aria-hidden and pointer-events none, with the rest of the screen dimmed. It follows the cursor, or the finger (and stays where it left), and hides when the cursor leaves the window. Moves are rAF transforms. Alt+R toggles it and an aria-live line announces it. It is mounted once in the app shell, which also re-syncs the classes when another tab changes them.
The quick Customize panel adds the readable font and ruler toggles. Segmented buttons are 44 px tall on phones.
Settings stays compact: two columns from lg up (Display, Reading comfort, hints | Account, Telegram, effects, Sound), and on phones every group is a disclosure (`components/settings/settings-group.tsx`) whose collapsed header sums up its values ("Dark · Medium text"), with only Display open, the choice kept per tab and `/settings#<group>` opening that group.

Native-language hints (students; Settings → Native-language hints: Off / Oʻzbekcha / Русский, and "At my level (A2–B1)" / Always) are optional secondary text; the exam stays in English. Off by default. A profile language that looks Uzbek or Russian is only a suggestion. `shouldShowL1Hints` shows them for A1–B1, band ≤ 5.0 or an unknown level (`lib/l1/level.ts` reads "B1", "Pre-Intermediate", "4.5" …). The level comes once per page load from the existing `GET /api/profile`, and Settings primes it from the server.
`lib/l1/hints.ts` is a curated, template-based translator with no AI and no network. It covers Reading / Listening instructions and answer rules, "Questions 1–6", the matching prompts, question-type names with a one-line tip, the Writing rubric (time, word count, "Summarise …", "To what extent …?") and the Speaking examiner's lines.
Honesty rules: unknown text → no hint, and one unknown sentence voids the whole hint (never partial). Numbers, ranges and letters are copied exactly. TRUE / FALSE / NOT GIVEN, YES / NO and names stay English, and content phrases stay English in «…». Uzbek uses ʻ (U+02BB) and ʼ (U+02BC). On the built-in papers (seeds, legacy, placement) every distinct instruction line gets a hint, and no question stem or option does.
`<L1Hint>` renders nothing on the server, before prefs load, for staff or without a translation, so there is no layout shift. It sits under question-group instructions and rules (practice and Mock CDI, in the CDI's own muted ink), the Reading passage rubric, result answer review, "Accuracy by question type" and "Your mistakes by type", the Writing runner and single-task editor, and the Speaking intro, examiner captions and cue card.
On a result's wrong answers, "Explain in Oʻzbekcha" / "Объяснить по-русски" calls `POST /api/l1/explain`: students only, zod-validated, ≤ 1200 characters, 503 without an AI key, `guardAi("l1-explain")` 40 a day, `unstable_cache` keyed by sha256(lang, text), never logged. The translation shows inline with `lang`, and loading and errors stay inline.
Not done: the Today session's step lines (mostly built from live numbers) have no hints yet.

### 10 — AI + teacher loop (done)

"Who needs help today" opens the teacher dashboard, right under the work-count chips. The pure ranker `lib/teacher/needs-help.ts` scores each of the teacher's students from: missed homework (deadline passed in the last 21 days, no submission), days without activity (≥ 4), a streak of 3+ that broke in the last two days, forecast skills trending down, the forecast overall ≥ 1 band under a target the student set, a question type with ≥ 3 wrong of its last 5, absences in the last 14 days, open peer-speaking reports, and Writing / Speaking work waiting for review over 48 h. Each signal adds a weight only past its threshold and never less as it grows, so the score is monotonic per signal. Order is score, then name, then id. Each row gets up to three reasons ("No activity for 6 days", "Missed 2 homework", "Matching headings: 4 of 5 wrong", "Listening trend falling") and one suggested step: Message, Mini task, Review or See report.
Honesty rules: no reason → not listed; the empty state is a calm "Everyone is on track today". Reports and the review backlog never go into the student's message. The target reason needs a target the student set and an overall forecast (all four skills).
The loader `lib/teacher/needs-help-load.ts` scopes to `teacherStudentIds` (lib/access) and runs one parallel batch: roster, last activity, absences and open reports (groupBy), recent homework with these students' submissions, waiting reviews, and two SQL projections (forecast evidence for the idea 2 model, graded Reading / Listening items with a per-student row limit). It reads no essays or transcripts. The catalog lists are already cached. The result is cached per teacher and Tashkent day for 5 minutes (`unstable_cache`, tag `needs-help:<teacherId>`), and the tag is revalidated by approve, undo and mini-task assign.
Row actions: Message opens `/messages?with=…&draft=…` with an editable draft (teachers only, never sent by itself). It is AI-written when a key is set (`draftStudentNudge`, `guardAi("teacher-nudge")` 60 a day), otherwise a template from the reasons. Mini task opens the sheet below; Open goes to the student's Learning DNA. "Done for today" hides a row on this device until the next Tashkent day (localStorage `averna_needs_help_done_v1`, with "Show N done today"). It shows 8 rows, then "Show all (N)". On phones rows stack and actions are 44 px, two per line, with no sideways scroll at 320 px; desktop rows are one compact line.
Merged rather than duplicated: the attention bar's "N students at risk" chip and the Teaching Assistant's "haven't practised in a week" tip became this list. Student Radar (health categories) stays on Insights.

AI draft → one-tap approval (teachers; admins keep the manual form): on `/teacher/reviews/[id]` a pending Writing / Speaking attempt opens on an "AI draft — check before approving" panel. It shows bands per criterion (TR/TA, CC, LR, GRA / FC, LR, GRA, P), 2–4 sentences of feedback and 1–3 next steps. The draft (`lib/review/draft-shared.ts`) reuses the assessment stored at submission. Without stored feedback text it makes one AI call (`draftReviewFeedback`, same bands, new words) and keeps the result in the attempt's existing `aiAnalysis.teacherDraft` (jsonb merge, no schema change). Without a key, Writing uses the stored heuristic text or `heuristicWritingAssessment`, and Speaking offers "Write feedback" (or approve the bands only).
Approve saves through the same `saveTestReview` path as the manual form (review, band, homework, mock, notification) via `POST …/approve`. The next pending attempt then opens with "Approved · Undo" for 6 s. Undo (`POST …/undo`) restores the snapshot taken just before the save: the previous review or none, the band, the homework submission and the mock sitting. It also removes the in-app notification. The snapshot is an HMAC-signed token bound to the reviewer and the attempt and lasts 2 minutes, and undo refuses if the review changed since (409). Edit makes every field inline, and Save goes through the same path with undo. Regenerate (`POST …/draft`) is `guardAi("review-draft")`, 80 a day (429), and 503 without a key.
Keys on desktop (never while typing): A approve, E edit, J / K next / previous pending attempt (`pendingNeighbours`, queue order and filters).

One-button mini task (needs-help row, student's Learning DNA page, review page): the pure `lib/teacher/mini-task.ts` takes the weakest type from the graded items (`lib/teacher/kind-stats.ts`, matching split into headings / information from the catalog's per-part kinds). It picks one part with idea 5's `pickPracticePart`, splittable papers first. A part the student already did is only picked when no weak type has an unseen one. Without mistakes it picks a fresh part of the weaker skill; with an empty catalog there is no task. The sheet shows "Matching headings · 1 part · ~20 min · due tomorrow", the reason and an editable title and due date (tomorrow 20:00 Tashkent). Assign (`POST /api/teacher/mini-task`) goes through `resolveExamContent` and the shared `createHomework` (now also behind "Set homework"). The task shows in that student's homework, Today session, calendar and reminders, and they get "New homework assigned".
Per-student homework is the additive nullable `Homework.assigneeId` (schema, deploy.sql, migration). Every student-facing homework read filters with `forStudent()` (lib/homework/audience). Teacher lists count a personal task against its one student and label it "Only <name>".
Every new route checks the session, the TEACHER role and `canReviewStudent`, validates with zod, and uses `trustedMutation` + `boundedJson`. No route sets its own function config.
Limits: homework targets a whole passage or part, so a Reading mini task is ~20 min (a Listening part ~8). `MistakeEntry` holds free-text corrections with no question type, so it doesn't steer the pick. TestReview has no field for "came from an AI draft", so that isn't recorded. A Telegram copy of an undone review notification can't be recalled. Old production code on a shared preview database would show a personal task to the whole group until production deploys. e2e/density.mjs checks the needs-help card at 320 px.

### 7 — Instant and offline (done)

Service worker v4 (`public/sw.js`). Its routing decisions live in the pure `public/sw-routes.js`, which the worker loads with `importScripts` and the tests run as-is.
- Cached: hashed `/_next/static/**` and fonts cache-first (at most 400 entries, oldest out); public images and icons stale-while-revalidate (80); the precached offline screen, logo and manifest. Activate deletes old `averna-*` versions only.
- Never cached: authenticated HTML, RSC payloads (`_rsc` / `RSC` header), anything under `/api`, other origins, non-GET, range requests, frames, and any response that is not a plain same-origin 200 or says `no-store` / `private`.
- The one page kept is `/offline`, a static client shell (`force-static`) with no personal data in its HTML. The worker stores it with every static file it names, all or nothing, when the first pack is saved, and refreshes it on visits (network first, cache after 4 s or offline). With it saved, a failed navigation redirects to `/offline?from=<page>` ("That page needs a connection"); without it, `/offline.html`, which links to saved lessons when they exist.

Instant: calm skeletons (`motion-safe` pulse, token colours) for Coach, Practice Studio, Homework, Articles, Flashcards and the Writing result; the others already had one. Flashcard grades are optimistic: the card advances at once, and the grade goes into a queue (`lib/offline/sync-queue.ts`, localStorage) with a client UUID and its moment, then syncs in the background. Offline it shows "Saved offline — N reviews will sync"; a server error gets one toast with Retry. A connection line ("You're offline — saved lessons still work · Open" / "Back online · syncing N reviews…", aria-live polite) sits above the phone tab bar and below drawers and full-screen lessons.

Offline packs ("Save for offline", 44 px, size shown first) live in IndexedDB (`lib/offline/idb.ts`, a small wrapper, no dependency), with their files in Cache Storage:
- Flashcards: a deck, or "Save my due cards" (today's queue as a snapshot, at most 200: overdue first, then 20 new).
- Articles: a reading lesson's text, words and exercises; an interactive lesson's HTML file, run offline in the same sandboxed, opaque-origin frame from a blob: URL, with its CSP as a `<meta>` tag.
- Listening: one recorded practice part, with its recording and questions. Answers can be typed but are not marked offline (the key never reaches the browser).
- `/offline` ("Saved on this device") lists the packs with size, date and Study / Read / Listen / Remove, storage used of 150 MB and Remove all. Views switch with `history.pushState`, so they need no server. It is linked from Settings → Account → Offline library, Profile and ⌘K "Offline library", not the sidebar.

Sync and conflict rule (`lib/srs-sync.ts`, no DB change). A queued grade is scheduled with the same SM-2 maths as of its moment, and `lastReviewedAt` is set to exactly that moment. The same grade again matches it and is ignored (duplicate); a grade older than the card's last review loses to the server state (stale), and the device adopts that state. Moments more than 10 minutes in the future or 60 days in the past are refused. Online reviews without a moment behave as before. Only applied reviews count toward XP, the streak, the activity log and Learning DNA. Grades are sent only while their author is signed in (checked against `/api/auth/session`).

Storage and privacy: everything saved stays under 150 MB and below 90 % of the browser quota (`navigator.storage.estimate`); saving asks for `navigator.storage.persist()`. Packs carry the user id. Another user signing in on the device wipes them, and every sign-out path (Settings, ⌘K, the avatar menu, change password, "Sign in as another user") first syncs waiting grades (≤ 2.5 s), then deletes the database, both offline caches and the queue, and sends `CLEAR_PRIVATE_CACHE`. Before this, nothing sent that message.

Limits: a recording is saved only when its host allows CORS; it is never stored as an opaque response, and the button says so. The browser may still evict packs under storage pressure: iOS Safari clears site data after about 7 days without a visit unless the app is on the home screen, and persistence is a request, not a guarantee. Parts read by browser voices, whole-test recordings, vocabulary games and the dictionary don't work offline. Images inside saved Listening questions and the lessons' web fonts need a connection. Playwright's offline mode doesn't cut the worker's own fetches, so e2e case 9 checks the page side and `tests/offline-privacy.test.ts` checks the worker.

### 3 — Live speaking partner and pronunciation map (done)

AI Coach → "Live speaking partner" (`/coach/live`, also in ⌘K; not in the sidebar). The setup screen offers Casual chat · IELTS Part 1 · Part 3 discussion, a topic from the existing Speaking material (`SPEAKING_TOPICS`, the seed's Part 1 topics and Part 3 discussions, `lib/realtime/topics.ts`) or "Surprise me", the minutes left today, the peer-speaking mic check with its level meter, and Start. Without an OpenAI key the page shows "Live partner isn't available right now" with a link to the AI Examiner, and no Start button.

Flow: the browser adds its mic track and the `oai-events` data channel, then sends the SDP offer to `POST /api/coach/live/start`. The route posts it with the session config to OpenAI's unified `POST /v1/realtime/calls` (multipart `sdp` + `session`, `OpenAI-Safety-Identifier` = sha256 of the user id). It reads the call id from `Location` and returns the SDP answer (`application/sdp`). The API key never reaches the browser. All OpenAI calls live in `lib/realtime/openai-realtime.ts`. The pure prompt builder (`lib/realtime/prompt.ts`) asks for a friendly partner: 1–2 sentence turns, follow-ups, no lectures, at most one gentle recast per turn, on topic, English only, a short refusal for unrelated or harmful requests, no personal data. The words are pitched to the student's level (the peer-speaking level). The session uses semantic VAD with low eagerness (it waits up to ~8 s, since learners pause), the `marin` voice, `gpt-4o-transcribe` for the student and `include: ["item.input_audio_transcription.logprobs"]`.

The call screen is phone first: a calm audio-reactive ring (transform only, still with reduced motion), a countdown with a "1 minute left" cue, captions for both sides (a side panel from lg up, a "Show captions" toggle), and 44 px Mute and End. Screen readers hear final caption segments only, politely. Keys: Space mutes (not while typing or on a control), Esc asks to end. A dropped connection gets 6 s, then one reconnect (a new call that replaces the old one). If that fails, the call ends and keeps the transcript. A hidden tab carries on. A phone call muting the mic shows "Paused". Closing the page ends the call with a keepalive request. A blocked mic or a browser without WebRTC gets plain help text.

Limits and the hard stop (`lib/realtime/limits.ts`, `lib/realtime/live-store.ts`, no schema change):
- 10 minutes per student per Tashkent day, 240 s per call (clamped to 60–270 s), 300 minutes per day for everyone, and `guardAi("realtime-speaking")` at 4 calls an hour and 6 a day. Under 30 s left, or over a cap → a friendly 429.
- Each call is one ActivityLog row (`LIVE_SPEAKING`, 0 points) holding the FULL length while open. Ending sets it to the server-measured length, never the client's and never more than the reservation. The start reserves, counts again with its own row and rolls back when over a cap, so races refuse, never overspend (property-tested over arbitrary interleavings).
- State changes are conditional writes on `details.state = "open"`: whoever settles a call hangs it up. A new start settles and hangs up the student's previous open call.
- The start route's `after()` waits the call's length + 5 s and then hangs the call up at OpenAI if the client hasn't, so a tampered client can't run up costs. The end route settles and hangs up too. No route sets its own function config.

"How it went" (phone and desktop): talk time, the student's words, words a minute over their speaking time (VAD start/stop per turn), filler words (the peer-speaking counter), the longest answer, and 3 tips. The tips come from ONE `gpt-4o-mini` call over the transcript (`POST …/tips`, `guardAi("live-speaking-tips")`, 8 a day). Without a key, at the limit or on failure, the numbers give 3 fallback tips. XP: 10 per call with at least 60 s of the student's speech (capped by the call's server-measured length), at most 3 calls a day, through `awardXp` with an idempotency key and the daily budget (`SPEAKING_SESSION_COMPLETED`, kind "live"). It counts as Speaking for the Daily Session.

Pronunciation map (`lib/realtime/pronunciation-map.ts`, pure). A word's clarity is the lowest exp(logprob) of its tokens, and below 0.5 it is "unclear". Names, numbers, fillers and short function words are never flagged. Only words in the shown transcript count, deduplicated, at most 12. Sound tips use spelling heuristics plus small curated lists for th, w / v, final -ng, short vs long vowels and word stress, labelled as tips, not errors. Unclear words get a dotted underline plus "(unclear)" for screen readers. Under "Words to practise", Hear it uses the browser's en-GB / en-US voice, and Say it records ~2.5 s for one transcription (`POST …/word`, `guardAi("live-word-check")` 80 a day; the target word is not given as a hint) → "Clear ✓" / "Try again".
Honesty rules: the copy says "Based on how clearly the speech recogniser heard each word — not a phonetic test". Without logprobs there are no unclear words, only sound tips, and the page says so.

Stored and not: no audio anywhere and no transcript on the server. The rows hold minutes, mode and topic id. The transcript stays in the tab (sessionStorage for the summary). Its text is sent once for the tips, and Say-it recordings are transcribed and dropped. Nothing logs an SDP or a transcript. Every route checks the session, the STUDENT role, `trustedMutation`, `boundedJson` (SDP ≤ 20 KB) or a bounded audio body (≤ 400 KB), and zod, with friendly 400 / 401 / 403 / 404 / 429 / 502 / 503 answers.

Env (in `.env.example`): `OPENAI_REALTIME_MODEL` (default `gpt-realtime-2.1-mini`), `OPENAI_REALTIME_TRANSCRIBE_MODEL` (`gpt-4o-transcribe`), `OPENAI_REALTIME_VOICE` (`marin`), `REALTIME_STUDENT_MINUTES_PER_DAY` (10), `REALTIME_MAX_CALL_SECONDS` (240, ≤ 270), `REALTIME_DAILY_MINUTES_CAP` (300).
Limits: the WebRTC call itself (audio, VAD and real logprobs) can't run in CI without a key. The routes are tested with OpenAI mocked at fetch, and e2e case 10 checks the "isn't available" card at 320 px. On iOS Safari the call needs HTTPS and a tap (the Start click primes audio), and the speaker can be quiet without headphones. The reconnect starts a new call, so the partner loses the earlier context.

Not in scope now: 4 (personal mistake deck) and 6 (Telegram Mini App — to be discussed separately with the owner).

## Shared principles

- Phone first, desktop comfortable.
- Phone tap targets ≥ 44 px; body text ≥ 14 px; no text smaller than 11 px.
- Light and dark themes through design tokens only.
- No new per-route function config (`maxDuration`, `preferredRegion`, `memory`).
- Every existing route keeps working.
- Student UI in English (native-language hints are optional secondary text); admin UI stays Uzbek.
- One commit per idea.
