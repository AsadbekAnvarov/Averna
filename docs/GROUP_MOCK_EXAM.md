# Teacher-led group Mock Exam (manual staging rollout)

This extends, rather than replaces, `docs/MOCK_EXAM.md`. The independent mode stays Listening → Reading → Writing, with Speaking separate. An in-centre group session has one responsible teacher, automatically marked objective papers, manually reviewed Writing, and an actual teacher-conducted Speaking test. It is an Averna simulation, not an official IELTS sitting.

## Teacher workflow

1. Open **Teacher → Mock analytics → Teacher-led sessions** (`/teacher/mock/sessions`). Choose a class you currently teach and a title. Only that teacher can start/collect/cancel, mark, publish or correct this session's grades; another teacher/admin cannot take ownership through the review endpoint.
2. Choose **unique Listening, Reading and Writing papers** (default). Registration stops at the smallest available ready-paper pool; with two Listening papers, strict uniqueness means at most two candidates. **Balanced repeats** is a separate explicit choice, capped at 30 candidates. It rotates the available variants with minimal repetition, not a promise of a different paper for everyone. No generated audio, new topics or AI authoring.
3. Share the class-only 8-character join code. Students use the group-mode panel on `/learning/mock-exam`. Only current, non-blacklisted members of that class with a live student role can join. An existing active independent mock must be completed/left first; it is never silently abandoned. A retry returns the existing participant/attempt, not a new draw.
4. Each student plays the introduction of their assigned existing recording and confirms headphones/readiness. Starting requires every joined candidate ready; readiness is a user confirmation, not automatic measurement of audio quality.
5. **Start everyone** schedules one 15-second countdown, using server timestamps. Listening follows each assigned recording's length + two minutes; Reading/Writing each have 60 minutes, without free breaks. Consequently students with different recording lengths may reach Reading at different times. Refresh does not reset the clock. The lobby opens the computer block at the start; mobile/browser autoplay may still require an explicit retry.
6. The roster shows variant number, section, server-time remaining, readiness and the last account update. An update timestamp is not proof a student is online or an anti-cheating detector. Polling is bounded, every five seconds, without overlapping requests.
7. **Collect and end** deliberately expires active section clocks; it cannot extend an already expired deadline. It collects confirmed account drafts, then blank later sections. Device-only unsaved work after the cutoff is not guaranteed. A confirmation warns about this. Cancellation abandons only active attempts and does not delete previously saved objective sections; a collected/published session cannot be cancelled.
8. Open a finished candidate in the review queue. Read both essays with the saved prompts and Task 1 chart/image reference; see word counts. Save partial private rubric drafts or fill all four criteria for each essay and Speaking. Choose each learner’s Speaking topics yourself; the app does not assign oral interview questions. Confirm you personally conducted Speaking Parts 1–3 and assessed pronunciation. Teacher feedback is shared only on publication.
9. **Publish** creates exactly two Writing tests, one in-person Speaking test and their teacher reviews in a transaction. It uses Task 2 double weighting, the four Speaking criteria, and four equally weighted skill bands for the rounded overall. No Writing/Speaking AI/provider calls or manual-grade XP. Re-publication is rejected, not duplicated. Recorded corrections use the existing reviewed-test pages and remain owner-restricted.

Speaking is explicitly `inputMode: "in-person"`, `teacherConducted: true`. The app does not invent a transcript, recording, Speaking time or recorded-answer evidence. Until release, Writing is **pending**, not an actual zero grade; no group overall is issued. Student session responses contain only their own participant, and omit unpublished results/teacher drafts. Published results/history distinguish teacher-led sessions from legacy four-section mocks.

## Reliability and access boundaries

- The old independent `cd-v1` rules, revision queue, immediate device envelopes, account-save acknowledgement, explicit offline/retry/conflict comparison and deadline collection are reused. Never present an unconfirmed save as saved.
- Group/session row locks serialize joins/start/end/cancel; live class assignment, blacklist and roles are rechecked. A transfer or role revocation denies access instead of handing the session to another teacher.
- Writing's accepted snapshot and finished computer-block update commit together under timestamp/current/status CAS. Failed snapshot writes roll back the completion; concurrent draft changes require reload. Prompts/structured charts are saved at collection so marking need not rely on a future edited catalogue.
- Review drafts/publication use participant-version checks and locks. Failed publication rolls back all manual tests/reviews/result changes. A stale teacher form keeps its entered text and reports the conflict; it is not silently overwritten by roster polling.
- Private/no-store responses, same-origin mutations, strict bounded bodies, authenticated scopes and shared user rate limits. Session code alone never grants class access. No live security requirements are disabled.
- Expired attempts are collected on candidate run views and eligible teacher roster polls. **There is no newly provisioned unattended scheduler.** If nobody visits/polls, finalisation may wait until the next permitted visit; deadlines themselves continue on the server. Keep the teacher dashboard open while invigilating. Real hosted latency and multi-tab/concurrent PostgreSQL behaviour still need staging acceptance.

## Exam comfort controls

The existing persistent light/dark ThemeProvider now has a 44px labelled toggle inside exam headers and Mock introductions/lobbies. It does not recreate a sitting or reset its answers/clock.

Reading highlights have four choices: **yellow, blue, green and pink**. Selected colour has a check mark and accessible name; text inherits the surrounding theme's ink. Selection and per-range colours persist on this device under the attempt key. Old numeric highlight spans remain compatible. Clear removes passage spans/colour entries; successful-submit cleanup removes both attempt stores. These are device reading aids, not cross-device account highlights or answer data.

## Rollout gate — do not enable production automatically

- `GROUP_MOCK_SESSIONS="off"` by default; disabled API returns 404 before authentication. Independent mocks and comfort controls do not depend on this flag.
- Review/apply **`prisma/migrations/20261010000200_group_mock/migration.sql`** only to a verified isolated staging DB after restoring a backup and reconciling migration history. Two new tables reference existing teachers/groups/students/attempts. The migration is intentionally NOT added to legacy automatic `deploy.sql`; ordinary deploy alone does not set up/enable group sessions.
- Generate the Prisma client, deploy matching code, set the staging flag to `on`, and check real current-class teacher/student authentication. Verify enough complete 40-question L/R papers, all four ready HTTPS/script-matching recordings, both Writing prompt pools and actual CDN playback. Teacher sessions never synthesize missing recordings.
- Acceptance: two real authenticated student devices + teacher, wrong class/owner, revoked roles/transfers/blacklist, capacity and balanced repeats, start-version race, device clock skew/suspended tabs, offline autosave/expiry, collect/cancel, essay snapshot atomic failure, two concurrent private drafts/publications, corrections, old individual/legacy history, retained privacy, actual Safari/Android/headphone/keyboard/accessibility.
- Roll back by turning the group flag off without dropping tables or rewriting stored results. Do not change active learners' `papers.mode`, owner or published metadata. A flag-off rollout requires an operational decision for active sessions; do not pretend their server clocks pause.
- The user requested merge once implementation and repository checks are ready. Keep all new staging flags off after any merge until the manual acceptance above. No production DB, real student, hosted setting, paid AI/provider or scheduler was used in local validation. Hosted deployment blocks must be resolved by the authorised maintainer, not bypassed.
